# 冒險島遊戲化：設計文件

日期：2026-10-31（第二階段，建立在第一版網站之上）

## 1. 目的與緣由

家長看過第一版後，希望網站**更生動、像遊戲、有可愛角色引導**，並給了參考站
（spell-ns-force.netlify.app：3D 低多邊形冒險島地圖、老師角色帶路、次主題集星、金旗、徽章、歡迎輸入名字）。
目標學生是國一、理解不足、考試不理想的孩子；遊戲化是為了**讓他願意每天打開、做完一關再做一關**，
不是為了炫技。所有學習內容與「重點 → 活動 → 測驗 → 錯題本」的結構維持不變。

家長在三條做法中選了**做法二：Three.js 真 3D 地圖**（而非 SVG 2.5D 或只加徽章）。

## 2. 目標、非目標、反目標

### 目標
- 首頁變成一張 3D 冒險島地圖：每個單元是一座島，依科目分區，島與島之間有木橋。
- 吉祥物「咕博士」（貓頭鷹）在地圖上站在目前進行中的島上；在單元頁用對話泡泡引導與鼓勵。
- 獎勵系統：每島 3 顆星（讀完重點、活動全做完、測驗 80% 以上）、集滿升金旗、經驗值與等級、成就徽章、連續登入天數。
- 第一次進站輸入名字，之後咕博士會叫名字。
- 完成一座島有慶祝動畫（彩帶）。
- 地圖可用滑鼠拖曳旋轉、滾輪縮放，手機可單指旋轉、雙指縮放。
- 雙擊 index.html 離線可用；手機透過 GitHub Pages 順暢。

### 非目標
- 不做登入、排行榜、多人。
- 不做音效（之後可加）。
- 不做地圖上的自由行走或角色動畫以外的 3D 互動。
- 不改任何既有的內容檔格式（單元內容檔不需要為地圖加欄位）。

### 反目標
- 地圖載不出來（舊手機、無 WebGL）就什麼都不能做：**必須有退路**，自動改顯示第一版的卡片清單。
- 為了遊戲感犧牲手機效能（卡頓、發燙）。
- 幼稚化：角色要可愛但語氣像一個會鼓勵人的學長姐，不是幼兒節目。

## 3. 限制

- 仍然是純靜態、無建置步驟、傳統 `<script>` 載入。
- Three.js 用 **UMD 版本（`three.min.js`，r158）下載後放在 `js/vendor/`**，不從 CDN 載入。
  理由：r160 以後只剩 ES module 版本，ES module 在 file:// 下無法載入；且本地放置可離線。
  這是規格 §3「外部資源只允許 Google Fonts」的明確例外，經家長選擇做法二而放寬。
- 不用 Three.js 的 examples 附加模組（OrbitControls、CSS2DRenderer 都是 ES module）；需要的功能自行實作小版本。
- 地圖的所有模型用 Three.js 內建幾何（六角柱、圓錐、圓柱、方塊、球）組合，不載入模型檔。
- 像素比上限 2，手機上限 1.5；島嶼總面數控制在數萬以內。
- 進度資料格式版本維持 1，**只新增欄位**（`player`），舊的進度檔仍可匯入。

## 4. 做法比較（已決定）

| 做法 | 取捨 | 結果 |
|------|------|------|
| 一、SVG 2.5D 島嶼 | 無相依、最輕，但沒有真 3D | 未選 |
| **二、Three.js 3D 地圖** | 最像參考站，可旋轉；多一個 650KB 的程式庫、需顧效能與退路 | **家長選擇** |
| 三、只加角色與徽章 | 最快但少了地圖 | 未選 |

## 5. 畫面與流程

### 首頁（地圖）
- 全畫面 3D 場景：藍色海面（頂點正弦波動畫）、天空漸層、若干裝飾小島。
- **生物區**在地圖左半、**社會區**在右半（地理、歷史、公民三條島鏈）。單元依 `order` 沿島鏈排列，相鄰島以木橋相連。
- 每座島：六角柱島身、沙色邊緣、幾棵低多邊形樹、一間小屋；島上方漂浮一個 HTML 標籤（單元編號＋名稱＋星數），由 3D 座標投影到 2D 定位。
- 島的狀態：未開始＝淺沙色；進行中＝綠色；完成（3 星）＝綠色＋金旗（旗子有飄動動畫）。
- 咕博士（3D 低多邊形貓頭鷹）站在「最近一次進入或最該做的島」上，輕輕上下浮動。
- 點一座島 → 鏡頭平滑飛近，然後進入該單元頁（既有畫面）。
- 左上 HUD：名字、等級與經驗條、★ 總星數 / 總數、旗 完成島數 / 總數。右上保留「進度」按鈕。
- 底部一行提示：「點一座島開始冒險」，咕博士的對話泡泡顯示當下建議（例：「小明，今天從『第1章 生命的世界』開始吧！」）。
- 右側（桌面）或下方可展開（手機）：**島嶼清單**，按科目列出所有單元與星數，是地圖的文字版，也是無 WebGL 時的退路畫面。

### 歡迎畫面
第一次（`player.name` 為空）進站：中央對話框，咕博士＋「歡迎來到國一冒險島！」＋名字輸入框＋「開始冒險」。
名字可在「進度」對話框裡修改。

### 單元頁（既有四分頁）
- 頂部標題旁顯示該島的 3 顆星（哪些已點亮）。
- 右下角固定一個小的 2D 咕博士，旁邊對話泡泡依情境換話：
  - 進入重點整理：「一次看一張，看完想想能不能講給別人聽。」
  - 活動完成：「漂亮！」「這題你已經會了。」（隨機）
  - 測驗答錯：「沒關係，看解析，為什麼是那個答案？」
  - 測驗結束 ≥80%：「拿到星星了！」；<80%：「再讀一次重點，再試一次就會更好。」
  - 錯題清空：「錯題本空了，太強了！」
- 點咕博士可收合泡泡。
- 拿到星星、徽章時，畫面上方滑出通知卡（「★ 獲得星星：讀完重點」「🏅 徽章：第一顆星」）。
- 一座島集滿 3 星：彩帶動畫 + 「回地圖看金旗」按鈕。

### 進度對話框
原有的匯出 / 匯入 / 清除，加上「名字」欄位與「徽章櫃」（已得／未得的徽章列表與說明）。

## 6. 獎勵規則（純邏輯，可測試）

### 星星（每島 3 顆）
| 星 | 條件 |
|----|------|
| 重點 | `conceptsDone` |
| 活動 | 所有活動完成 |
| 測驗 | `bestScore / quizTotal >= 0.8` |

金旗 = 3 顆都有。**單元「完成」的定義改為 3 星**（取代第一版的 `isUnitDone`，第一版的「測驗做過即可」太寬）。

### 經驗值
- 讀完重點 +20、完成一個活動 +15、測驗每答對一題 +5、測驗首次達 80% +30、錯題重練答對 +10。
- 等級 = `floor(sqrt(xp / 60)) + 1`，顯示「Lv.3 ・ 120 / 240」（到下一級所需）。

### 徽章（可擴充的清單，各有 id、名稱、說明、條件）
| id | 名稱 | 條件 |
|----|------|------|
| first-star | 第一顆星 | 任一星 |
| first-flag | 第一面金旗 | 任一島 3 星 |
| perfect | 全對！ | 任一測驗滿分 |
| clean-book | 錯題清零 | 曾有錯題且清空 |
| streak-3 | 連續三天 | 連續 3 天有學習紀錄 |
| streak-7 | 連續七天 | 連續 7 天 |
| bio-all | 生物島主 | 生物所有島金旗 |
| soc-all | 社會島主 | 社會所有島金旗 |

### 連續天數
每次有學習動作（讀完重點、完成活動、完成測驗、重練答對）記錄當天日期（本地時區 `YYYY-MM-DD`）；
與前一次相差 1 天則 `streak + 1`，同一天不變，中斷則重設為 1。

### 計算方式（實作者的決定）
星星、經驗值、徽章**全部由進度狀態推算**，不用事件累加：
- 重測、重讀不會重複給分（刷同一份測驗無法升級）。
- 既有進度與匯入的進度檔自動回填等級與徽章。
- 為此每個單元多存兩個欄位：`rightEverIds`（曾經答對過的題目 id，測驗與重練都會加入）與 `resolvedCount`（重練答對而移出錯題本的次數）。舊資料缺這兩欄時，`rightEverIds` 以空陣列起算（XP 略低於實際，可接受）。
- 經驗值 = Σ 每單元（讀完重點 20 ＋ 完成活動數 × 15 ＋ `rightEverIds` 數 × 5 ＋ 測驗曾達 80%？30：0 ＋ `resolvedCount` × 10）。
- 徽章 = 依狀態算出的集合；另存 `badgesSeen`（已通知過的徽章 id），新出現的徽章才跳通知。
- 連續天數與名字是唯一的「事件」資料，存在 `player` 裡。

### 地圖規模（實作者的決定）
以三個年級約 60 座島設計：每條島鏈（生物一條、社會三條）採**蛇形**排列，每排 6 座；島間距固定，橋只連同鏈相鄰單元。
鏡頭初始對準「目前進度所在」的島；縮到最遠時只顯示金旗島與目前島的標籤，其餘標籤隱藏。目前只有 4 座島時版面照樣成立。

### 進度資料新增欄位（version 仍為 1）
```json
"player": {
  "name": "小明",
  "badgesSeen": ["first-star"],
  "streak": { "count": 3, "last": "2026-10-31" },
  "lastUnit": "bio-ch1"
}
```
每單元另加 `"rightEverIds": [], "resolvedCount": 0`。`parseState` 對缺少這些欄位的舊資料給預設值。

## 7. 技術架構

```
js/vendor/three.min.js        Three.js r158 UMD（下載放置）
js/game-logic.js              星星、金旗、經驗值、等級、徽章判定、連續天數（UMD，node:test）
js/progress.js                新增 player 欄位與方法：setName / addXp / touchStreak / awardBadge / setLastUnit
js/mascot.js                  2D 咕博士 SVG 字串（幾種表情）＋ 對話泡泡元件 ＋ 通知卡 ＋ 彩帶
js/map/scene.js               建場景：海、天空、燈光、鏡頭、自製拖曳旋轉與縮放
js/map/island.js              建一座島（六角柱、樹、屋、旗）與 3D 咕博士
js/map/layout.js              依 content 計算每座島的位置與橋（純函式，可測）
js/map/labels.js              3D → 2D 投影的 HTML 標籤
js/views/map.js               首頁：建場景、HUD、清單面板、點擊飛近、退路
js/views/welcome.js           歡迎對話框
css/game.css                  HUD、泡泡、通知、彩帶、清單面板
```

`index.html` 載入順序：three.min.js → 共用模組 → game-logic → mascot → map/* → views/* → 內容 → app.js。
`app.js` 的 home 路由改呼叫 `APP_VIEWS.map`；WebGL 不可用時 `APP_VIEWS.map` 自行退回卡片清單。

### 鏡頭與操作
透視鏡頭，俯角約 35 度看向地圖中心。拖曳：繞中心水平旋轉；滾輪或雙指：縮放（限制範圍）。
點島：raycaster 命中島身 → 鏡頭用 600ms 緩動飛近 → 導向單元路由。

### 效能
`renderer.setPixelRatio(Math.min(devicePixelRatio, isMobile ? 1.5 : 2))`；
畫面不動時降為每秒 30 幀；`visibilitychange` 隱藏時暫停；離開首頁時 `dispose` 場景與 renderer。

### 退路
`try { new THREE.WebGLRenderer() } catch` 失敗或 `WebGL` 不支援 → 不建場景，直接顯示島嶼清單（即第一版的科目卡 + 單元卡），HUD 與咕博士泡泡照常。

- `tests/progress.test.js` 新增：`player` 預設值、舊格式匯入後 `player` 有預設、`setName/addXp/awardBadge` 不重複、`touchStreak`。

# 國一生物與社會互動自學網站：設計文件

日期：2026-10-31

## 1. 目的與緣由

一位家長要為自己國中一年級的孩子做一個在家自學網站，科目是**生物（康軒版）**與**社會（南一版）**。
孩子對這兩科**理解不足、考試成績不理想**。家長明確要求網站要有**互動性**，
目的不是題庫式反覆刷題，而是透過操作讓孩子把觀念弄懂。

現有的 GitHub 專案多半是單一單元、沒有授權、無法擴充。這個專案要做一個
**自己維護、免費上線、之後加單元只需新增內容檔不必碰程式**的互動自學網站。

使用者只有這一個家庭（孩子操作，家長偶爾看進度）。沒有老師端、沒有其他同學。

### 針對「理解不足」的設計原則
- 每張概念卡**先給生活例子或圖，再引出名詞**，不以定義開頭。
- 互動活動以**理解型**為主（分類、排序、圖片標示、配對、填空），純記憶型（翻牌）為輔。
- 每題解析寫清楚**為什麼對、其他選項為什麼錯**，不只給答案。
- 錯題本**按概念分組**，直接顯示哪個觀念弱。
- 一章拆成五到六個小概念，介面鼓勵一次只做一個。

## 2. 目標、非目標、反目標

### 目標
- 學生打開網站，選科目、選單元，依序完成「重點整理 → 互動活動 → 測驗」。
- 測驗答完立即顯示對錯與解析；錯題自動進錯題本，可重練。
- 網站記住每個單元做到哪、測驗最高分、錯過哪些題。
- 手機、平板、電腦都能順暢使用。
- 放上 GitHub Pages 免費上線；也能直接雙擊 `index.html` 離線使用。
- 新增單元只要加一個內容檔並登記到清單，不需修改共用程式。

### 非目標
- 不做登入、帳號、跨裝置同步。
- 不做老師後台、成績回報、班級功能。
- 不做留言、排行榜、社群功能。
- 不做影片託管。

### 反目標（做了反而算失敗）
- 直接抄錄康軒、南一課本的文字或題目（版權問題）。內容必須是依課綱概念**原創撰寫**。
- 需要安裝任何軟體、跑伺服器或建置步驟才能打開。
- 使用需付費或會過期的外部服務。
- 介面幼稚化（這是給國中生，不是國小生）。

## 3. 限制

- 純靜態：HTML、CSS、JavaScript，**不用任何框架、不用打包工具、不用 npm 相依套件**。
- 必須能在 `file://` 直接開啟。因此：
  - 不能用 `fetch()` 讀 JSON（Chrome 在 file:// 下會擋）。
  - 不能用 ES module（同樣受 CORS 限制）。
  - 內容檔用**傳統 `<script>` 載入的 .js 檔**，每個檔案把自己登記到全域清單。
- 繁體中文介面與內容。
- 進度存在 `localStorage`。
- 外部資源只允許 Google Fonts（字型）；沒網路時退回系統字型，功能不受影響。
- 內容依 108 課綱的概念與兩家出版社的**單元順序**編排，文字與題目自行撰寫。

## 4. 做法比較

| 做法 | 內容 | 取捨 |
|------|------|------|
| **一、純靜態 + localStorage**（採用） | 無後端，內容放 .js 資料檔，進度在瀏覽器 | 最簡單、免費、好維護；進度只在該裝置 |
| 二、靜態 + Google 試算表回報 | 同上，測驗完把分數寫進 Google 試算表 | 需設定 Apps Script；使用者只有一人，沒有看別人成績的需求，多餘 |
| 三、完整前後端 + 登入 | 帳號、資料庫、跨裝置 | 要租主機與維護，對單人自用負擔過重 |

使用者選擇**做法一**，理由：只有自己用，不需要任何回報或同步功能。
架構仍保留日後加做法二的可能（測驗完成時有一個明確的「結果」事件可掛接）。

## 5. 網站結構

單一 `index.html`，用 URL hash 做頁面切換（例如 `#/bio`、`#/bio/ch1`、`#/soc/geo/l1`）。
這樣在 file:// 與 GitHub Pages 都能正常運作，瀏覽器上一頁也有效。

```
首頁
├── 生物（康軒）
│   └── 單元清單（依課本章節順序）
│       └── 單元頁：重點整理 / 互動活動 / 測驗 / 錯題本
└── 社會（南一）
    ├── 分頁：地理
    ├── 分頁：歷史
    └── 分頁：公民
        └── 各自的單元清單 → 單元頁（同上）
```

### 首頁
- 兩張大卡片：生物、社會。各顯示該科完成進度（已完成單元數 / 總單元數）。
- 右上角：「進度」按鈕，可匯出進度為 JSON 檔、匯入 JSON 檔、清除全部進度（需二次確認）。

### 科目頁
- 生物：單元卡片清單。
- 社會：頂部三個分頁（地理、歷史、公民），切換後顯示該線的單元卡片。
- 每張單元卡片顯示：單元名稱、三個小圖示代表重點 / 活動 / 測驗各自完成狀態、測驗最高分。

### 單元頁
頂部固定一列四個分頁：**重點整理、互動活動、測驗、錯題本**。

1. **重點整理**：若干「概念卡」，每張有標題、簡短說明（兩到四句）、可選的關鍵詞列表。
   捲到底或點「我讀完了」即標記完成。
2. **互動活動**：該單元 2 到 4 個活動，每個活動完成後顯示 ✓。活動型態見第 6 節。
3. **測驗**：8 到 12 題單選題，一次一題。選答後立即顯示正確與否、解析，才能下一題。
   結束顯示分數、花費時間、答錯的題目列表。錯題自動進錯題本。可重測，記錄最高分。
4. **錯題本**：此單元所有答錯過且尚未在重練中答對的題目。可逐題重練；答對即移出。

## 6. 互動活動型態

共用程式提供以下可重用的活動元件，每個單元的內容檔從中挑選並填入資料：

| 型態 | 說明 | 適合 |
|------|------|------|
| `match` 配對 | 左欄詞、右欄解釋，拖曳或點選配對 | 名詞與定義 |
| `sequence` 排序 | 把打亂的卡片拖成正確順序 | 流程、層次、年代 |
| `label` 圖片標示 | 一張圖（內嵌 SVG），把名稱拖到正確位置 | 細胞構造、台灣地圖 |
| `fill` 填空 | 句子挖空，從選項拖入或點選 | 關鍵詞 |
| `flashcard` 翻牌 | 正面問題背面答案，自評「記得 / 不記得」 | 名詞記憶 |
| `sort` 分類 | 把項目拖進正確的籃子 | 生物 vs 非生物、三權分立 |

全部活動都要同時支援滑鼠拖曳與觸控，並提供「點選模式」做為替代（先點項目再點目標），
確保手機上一定能完成。

圖片用內嵌 SVG，由內容檔提供；不引用外部圖片，避免版權與離線問題。

## 7. 內容檔格式

每個單元一個檔案，放在 `content/<科目>/<線>/<單元id>.js`，例如
`content/bio/ch1.js`、`content/soc/geo/l1.js`。檔案內容：

```js
window.APP_CONTENT.register({
  id: "bio-ch1",
  subject: "bio",          // "bio" | "soc"
  track: null,             // 社會才有："geo" | "hist" | "civ"
  order: 1,                // 在清單中的順序
  title: "第1章 生命的世界",
  publisher: "康軒",
  summary: "一句話說明這單元在學什麼",
  concepts: [ { title, body, keywords: [] }, ... ],
  activities: [ { type: "match", title, data: {...} }, ... ],
  quiz: [ { id, concept, question, options: [..], answer: 0, explanation }, ... ]
  // concept：對應 concepts 中某張概念卡的標題，供錯題本分組
  // explanation：寫「為什麼對」以及「其他選項為什麼錯」
});
```

`index.html` 用 `<script>` 依序載入 `content/manifest.js`（列出所有內容檔路徑）再載入各內容檔。
新增單元 = 新增一個內容檔 + 在 `manifest.js` 加一行。

每種活動型態的 `data` 欄位結構由共用程式定義並寫在 `docs/content-format.md`，
讓日後寫內容時有範本可抄。

## 8. 進度資料

存在 `localStorage` 的單一鍵 `jh-learn-progress`，內容為 JSON：

```json
{
  "version": 1,
  "units": {
    "bio-ch1": {
      "conceptsDone": true,
      "activitiesDone": ["a1", "a2"],
      "bestScore": 9,
      "quizTotal": 10,
      "attempts": 2,
      "wrongIds": ["q3", "q7"]
    }
  }
}
```

匯出 = 把這個 JSON 下載成檔案；匯入 = 讀檔後覆蓋（需確認）。
日後若格式變動，用 `version` 欄位做遷移。

## 9. 首批內容範圍

第一版要包含以下單元的完整內容（重點、活動、測驗）：

- 生物（康軒七上）：**第 1 章 生命的世界**
  概念涵蓋：生命現象、細胞的發現與構造、動植物細胞比較、顯微鏡使用、生物體的組成層次。
- 社會（南一七上）：
  - 地理 **第 1 課 台灣的位置與範圍**：經緯度與位置、相對位置、領土範圍、時區。
  - 歷史 **第 1 課 史前台灣與原住民**：考古遺址、舊石器與新石器時代、金屬器時代、原住民族分布。
  - 公民 **第 1 課 自我與家庭**：自我概念、青春期變化、家庭功能與型態。

其餘單元之後依課本順序逐一加入，格式相同。

內容深度以國一程度為準：每個概念卡兩到四句話，不堆術語；題目難度大致對應段考基礎題到中等題。

### 內容正確性（實作者的決定）
實作者手上沒有課本，內容依 108 課綱核心概念撰寫。因此：
- 只出**課綱核心概念**，避開各版本會不同的細節數字、年代與專有名詞寫法。
- 每個內容檔開頭加註解：「本單元內容為原創撰寫，請對照課本校對後使用」。
- 內容檔格式要讓**非工程師能看懂、能直接改**：欄位用中文註解說明，驗證腳本的錯誤訊息要指出是哪個單元、第幾題、哪個欄位。
- 家長手邊有課本，上線前自行對照一遍；之後發現錯誤直接改內容檔即可。

### 裝置與離線（實作者的決定）
孩子的主要裝置未知。假設：手機或平板**連網**透過 GitHub Pages 使用；電腦可**離線**雙擊 `index.html` 使用。
第一版**不做** service worker 手機離線快取。拖曳互動優先在手機尺寸實測觸控。
每題的概念標籤（`concept` 欄位）用來把錯題本按概念分組。

## 10. 視覺與體驗

- 風格：乾淨、現代，給國中生的感覺（不是卡通幼兒風）。兩科各有一個主色。
- 支援淺色與深色模式（跟隨系統）。
- 字體夠大，手機單手可操作；拖曳目標區至少 44px。
- 所有狀態（完成、未完成、答對、答錯）同時用顏色與圖示表示，不只靠顏色。
- 頁面切換不重新載入，狀態不閃爍。

## 11. 測試與驗證

- **內容驗證腳本** `tools/validate-content.js`：用 Node 執行，檢查每個內容檔的欄位齊全、
  題目答案索引在範圍內、活動 data 符合該型態的結構、id 不重複。寫內容時先跑這個。
- **邏輯單元測試**：進度儲存、測驗計分、錯題本進出的純邏輯抽成獨立函式，
  用 Node 內建 `node:test` 測試，不需安裝套件。
- **瀏覽器手動驗證**：在手機寬度與桌面寬度各走一次完整流程（首頁 → 單元 → 三個分頁 → 錯題本重練），
  並確認 file:// 直接開啟可用。

## 12. 交給實作者決定的事

- 檔案與函式的具體命名、CSS 的組織方式。
- 拖曳的實作細節（原生 Drag and Drop API 或 Pointer Events），只要滿足第 6 節的觸控與點選模式要求。
- 動畫與過場的多寡。
- 概念卡的確切文案與題目的確切題幹，只要符合第 9 節的範圍與深度。
- SVG 插圖的畫法。

## 13. 專案位置

目前在 app 為此對話建立的暫存資料夾中開發。完成第一版後再移到使用者指定的資料夾，
並初始化 git、設定 GitHub Pages。
